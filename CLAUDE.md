Guidance for Claude Code when working with this repository.

---

## Repository Overview

GPSA meet results archive, served at `results.gpsaswimming.org`. Contains all dual meet result HTML files organized by season year, historical invitational meet files, and the scripts that build and maintain the archive indexes.

---

## Structure

```text
/
├── 2022/                    # Dual meet results by season year
├── 2023/
├── 2024/
├── 2025/
│   ├── YYYY-MM-DD_T1_v_T2.html   # Individual meet result files
│   ├── divisions.csv              # Division assignments for archive builder
│   ├── index.html                 # Auto-generated season archive (do not edit)
│   └── scores.json                # Auto-generated scores feed (do not edit; gitignored)
├── 2026/
├── invitationals/           # Historical invitational static files (PDFs, meet invites)
│   ├── CityMeet/
│   ├── SummerSplashInvitational/
│   └── MiniMeet/
├── _headers                 # Cloudflare Pages headers (CORS for scores.json feeds)
├── index.html               # Root index — auto-generated by generate-indexes workflow
└── scripts/
    ├── build_season_index.py     # Season archive generator
    ├── build_scores_json.py      # Per-season scores.json feed generator
    ├── generate_index.py    # Directory index page generator
    └── bulk_process_results.py
```

## GitHub Actions

### deploy.yml

Triggers on every push to `main`. Runs sequentially:

1. `generate_index.py` — builds directory listing indexes for root and `invitationals/`
2. `build_season_index.py` — builds season standings/schedule page for each year directory (overwrites plain listing with rich archive)
3. `build_scores_json.py` — builds `scores.json` for each year directory (see below)
4. Deploys full working tree to Cloudflare Pages project `gpsa-results` — nothing is committed back to the repo.

Requires GitHub Actions secrets: `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID`.

## Scores feed (`scores.json`)

Each season directory publishes `scores.json` at `results.gpsaswimming.org/<year>/scores.json`.
It is the cross-repo data feed consumed by the **meet-schedule** site
(`meet-schedule.gpsaswimming.org`, repo `web-schedule`), which fetches it client-side
to show each dual meet's final score and a link to its result page.

- Generated by `scripts/build_scores_json.py`, which reuses `parse_meet_file()` and the
  team-name maps from `build_season_index.py` — score extraction is **not** duplicated.
- One record per swum meet: `date`, `home`/`away` (official abbrs), `home_name`/`away_name`
  (short schedule display names — the join key used by the schedule site, because abbrs
  drift e.g. Wythe = `GWRA`/`WYTHE`), `home_score`/`away_score`, and `url`.
- Built at deploy time from the committed HTML and gitignored (like `index.html`) —
  self-healing, so adding a result the normal way keeps the feed current with no extra step.
- `_headers` adds `Access-Control-Allow-Origin: https://meet-schedule.gpsaswimming.org`
  so the schedule site can fetch it cross-origin.

## Adding Meet Results

1. Add the result HTML file to the correct year directory: `YYYY/YYYY-MM-DD_T1_v_T2.html`
2. Ensure `divisions.csv` exists in that year directory
3. Push — `build-season-archive.yml` auto-regenerates the season archive

## Adding Invitational Files

1. Add files to the appropriate `invitationals/` subdirectory
2. Push — `generate-indexes.yml` auto-updates the directory index

## Scripts

See `scripts/` for documentation within each file. Run locally with:

```bash
# Rebuild a season archive manually
python scripts/build_season_index.py -i 2025 -o 2025 --non-interactive

# Rebuild a season's scores.json feed manually
python scripts/build_scores_json.py -i 2025 -o 2025

# Regenerate all directory indexes
python scripts/generate_index.py .
```
